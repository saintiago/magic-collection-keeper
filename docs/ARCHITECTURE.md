# Architecture

## Home and view navigation

`home-history.js` stores bounded real activity (12 distinct card identities/printing fallbacks and 12 stable tag IDs) through a plain storage port under `keeper-home-v1` plus the verified snapshot account/environment key. It stores only card references, escaped-on-render names and optional allowlisted public Scryfall image URLs; no quantities, assignments, credentials or pending imports. `home.js` composes activity with current collection/tag state and recent search choices; `home-view.js` renders at most six cards and four deck/other-tag links. Existing search choices are honest fallback activity, not fabricated chronology. Current tags resolve IDs/labels; deck classification uses location type and deck kind, including source-created locations. No activity yields **Your decks/tags**, not **Recent**. Unknown, saved and failed collection state retains the existing ownership icon semantics.

The app records actual detail opens, tag navigation and successful tag creation/rename. Merely loading, fetching, filtering a catalog query, or importing a pending draft cannot create Home ownership or invented activity. Clear removes only the active account's Home/search history; sign-out clears visible/in-memory state. Storage failures remain explicit with usable visit-only activity. Hidden Home DOM is removed, and Home never renders the full collection grid. The existing collection load remains client-wide to support ownership and filters; this change does not claim server pagination.

`screen.js` owns compact view presentation and route interpretation: default/`#home`, `#collection`, `#catalog`, `#import`, existing `#tag=<ID>`, and `#card=<printing UUID>&oracle=<Oracle UUID>` with optional exact-language/owned-entry references. `app.js` coordinates route state, search cancellation and callbacks; `tag-navigation.js` keeps stable tag links and Back/Forward synchronized with explicit view changes. Clearing a tag now targets `#collection`. The full inventory, scanner, exact printing review and import controllers remain separate. The small Home link and one action row replace the large sidebar, wordmark and introductory copy; sign-out stays visible and version details remain in the footer.

## Navigation and modal design policy

Prefer separate routes/pages for substantive workflows, card details and large forms. Each should have a clear Back action that returns to its most recent origin. This follows **LIFO** stack order (last in, first out), as browser history does; a FIFO queue would return to the oldest page and is unsuitable for Back navigation. Forward should remain predictable where supported.

Keep navigation state bounded and isolated to the verified account. Preserve the originating search text/results, filters, active tag, scroll position and focus when useful; keep private collection snapshots out of URLs and public caches. Clear private in-memory navigation state on sign-out or account change. Use validated stable references for deep links and reload, resolve owned entries again within the authenticated account, and show a recoverable error when a reference is unavailable. Abort pending work on departure and use request generations to prevent late responses from reopening or overwriting a newer page.

The dedicated card page is the current implementation example: browser history contains card references and opaque origin keys; up to twenty origin views live only in memory. Back restores the prior view and focus, while reload resolves the referenced identity/printing and ownership afresh. This does not promise persistence of the entire in-memory stack across reload or introduce a second generic navigation framework.

Reserve modals for brief confirmations and small focused auxiliary edits, such as printing/language selection or tag assignment. Primary navigation and large multi-step forms should normally be pages. Apply this default to new work and changes where appropriate; this policy update does not require migrating every existing modal. Record concrete changed behavior in use cases and test it when implementation changes.

## Collection loading and device snapshots

`public/recent-searches.js` owns a separate bounded localStorage history through plain-object storage ports. The schema-1 key includes the same origin/API/client/verified owner identity as collection snapshots, but is independent of the public name cache and inventory snapshots. It stores at most ten validated card references or submitted query strings, deduplicated by Oracle identity or normalized query and ordered by last selection/submission. It stores no ownership counts, tags, credentials or individual keystrokes. Recent card badges are derived from the current collection state. Grid selections and autocomplete selections share the common card detail; recent query selections run the existing unified search.

History starts only after `collectionIdentity()` returns a server-verified account (or the isolated local identity). Logout clears in-memory entries and rendered controls; saved history remains for the same verified account's later visit. Clear removes only the active account's history. Storage read/write failures retain ordinary searching and report unavailable persistence; failed removal retains the entries and a retryable message rather than claiming deletion. Empty focused input shows history/loading/empty/error states using the existing keyboard/touch listbox controller. The clear button is a stable element above the dropdown, so neither option overlap nor blur-driven dropdown removal can cancel its click/tap. Storage is local to this browser and is not synchronized across devices or open tabs.

`public/tag-view.js` centralizes escaped tag links and styles for every tag kind. `public/tag-navigation.js` handles the `#tag=<stable ID>` fragment, delegated link activation and browser history. `public/collection-view.js` renders card-opening buttons separately from sibling tag links, avoiding nested interactive controls. Tag navigation resets conflicting filters, closes dialogs and focuses the library heading. The selected ID is independent of the option registry so cached data, rename, deleted/empty tags and delayed refresh cannot silently select all cards. Assignment select/checkbox controls retain their editing semantics with separate navigation links. Tag-controller request generations prevent late reads reopening closed dialogs or replacing newer tag definitions.

`public/collection-counts.js` calculates display quantities from per-location assignments, not pooled ownership or array length. It preserves distinct printing/finish/condition entries and sums all matching allocations. `public/deck-source-view.js` renders source totals as current source lot allocations plus explicit pending quantities, independently of historical contributed/loose copies and manual location edits. No inventory mutation or import change is involved. Cached row tag metadata seeds the filter choices immediately; the existing tag refresh reconciles the full registry. The cache DTO/schema remains compatible.

`public/collection-loader.js` owns unknown/loading, updating, ready and failed states independently of catalog searching. Its plain-object load/cache ports let tests control response order and storage failures. Only a successful validated response establishes authoritative rows, including a genuinely empty array. Cards render immediately; loading tag options cannot delay them. Totals calculate synchronously from displayed rows, so there is no separate or simulated calculating phase.

`public/collection-cache.js` stores complete display snapshots in IndexedDB (schema 1), accommodating the large printing DTO without localStorage's small string quota. Keys include schema, frontend origin, API environment, Cognito client and verified account UUID. The protected `GET /api/session` transport endpoint returns only the JWT-authorizer subject. The browser remembers that server-verified identity with the signed-in session, preserving it on Cognito refresh. It never selects a cache account by decoding an unverified JWT. Local mode uses a separate origin/environment and fixed local identity.

Snapshots contain rows and last successful load time, never tokens or passwords. They are display hints, not authorization or replacement inventory. First use in an existing session obtains server identity; subsequent reloads can display the snapshot before collection loading. Corrupt/wrong-schema snapshots, blocked storage and quota failures fall back to normal loading. Cached cards carry their age and refresh/failure status. Images still need a network; browsers may evict snapshots.

Request generations reject out-of-order reads, reads started before mutations and previous-account results. Successful inventory mutation responses replace the snapshot; other writes invalidate it and their controller refreshes inventory. Batch partial successes update the snapshot per successful write. Logout invalidates pending work, clears session and snapshots, and broadcasts logout to other tabs; restored back/forward pages reload. Storage operations are serialized with invalidations so pending saves do not resurrect removed data.

## Deployment identity and coherent assets

`scripts/release.mjs` creates `baseVersion+deploy.runNumber.attempt` metadata, rejects older/equal published counters, and packages frontend assets under immutable `/releases/rN-aA/` paths. Only the deploy job, after test success, prepares deployment metadata. Each retry has a distinct attempt. Local `public/release.js` says local development. Production metadata is compiled into that release's module: the footer never fetches a latest-version pointer to relabel old JavaScript. About includes exact commit, UTC deployment start and Actions checks link, without claiming checks have passed.

Deployment uploads immutable assets first and publishes root HTML last. Imports, configuration and recognition paths resolve within their release prefix. Prior prefixes and legacy root assets remain available to older tabs. Root HTML/config use no-store and CloudFront invalidation; the existing managed cache policy has a one-second edge minimum. Backend builds receive the same metadata and return version/commit headers. Domain/application code has no dependency on deployment tooling.

The composition roots are `server.js` (local HTTP + SQLite) and `cloud.mjs` (API Gateway + Lambda). Both create the same application service. Dependency direction is **transport → application → domain**. Adapters implement plain object ports supplied by the composition root. Domain and application code import no browser, AWS, or Scryfall SDK.

## Inventory identity and invariants

1. A gameplay identity uses `oracle_id`; an exact language-specific printing uses Scryfall `id`. An identity can have many printings.
2. Owned inventory is separate from the catalog. Searching/caching never creates ownership.
3. Entries merge only for the same printing, language, condition and finish. Quantities are integers from 1 to 100,000, including the merged total.
4. Language comes from the canonical printing, never from an arbitrary write payload. Finishes must occur in that printing's supported finishes. Conditions are NM, LP, MP, HP or DMG.
5. Cloud ownership comes only from the verified JWT `sub`. A request body cannot select another owner. Each query/write is scoped to `USER#sub`.
6. Retrying an add with the same operation UUID and identical input is idempotent. SQLite records the operation in the same transaction. DynamoDB transacts the quantity change and a seven-day operation marker. Changed input with a reused UUID is rejected. Reopen the card or start a new batch after such a rejection.
7. Camera and pasted-text batch saves are per-entry, not a transaction spanning the whole batch. Already saved rows are retained as saved when a later entry fails, and a retry skips them. The server's operation marker protects a retry after an ambiguous network response.

SQLite tables: `card_identities`, `printings`, `inventory`, `api_cache`, `operations`. Cloud DynamoDB partitions: `USER#sub` for owned records (printing metadata snapshot included), `PRINTINGS`, `IDENTITIES`, `SEARCH`, `RATE`, and `OPERATIONS#sub`. Search data expires after one day; cached printing data after 30 days; owned inventory never expires. Snapshot metadata ensures previously owned cards remain browsable after cache expiration.

## Tags, allocations and source inventory

Source validation accepts `moxfield` with its original opaque deck ID, or `wizards-precon` with a `wizards:<set>:<product>:<edition>:<language>` identity and an HTTPS `magic.wizards.com` news URL. The colon namespace cannot collide with existing Moxfield IDs, so existing keys and import fingerprints remain unchanged. Wizards fingerprints also include provider and canonical source URL. The same source planner, permanent contribution high-water marks, atomic document commit, exact-printing finish checks and stable location tags serve both providers. Source UI labels official links accurately. Product definitions are reviewed data passed to the existing import port, not hardcoded app inventory or automatically inferred ownership.

`domain/tags.js` defines location/role/category types and validates opaque UUID identities separately from editable labels. `domain/deck-import.js` normalizes resolved deck snapshots and computes changes without I/O. `application/tagged-collection.js` composes inventory with tags, assignments and source contributions. `application/routes.js` is the shared transport dispatcher; concrete stores remain composed in `server.js` and `cloud.mjs`. `public/tags.js` owns the tag dialogs and escaped badge rendering.

The document port exposes owner-scoped `get`, `list`, compare-and-swap `commit`, durable `saveCards`, and `withInventoryLock`. SQLite adds a `documents` table at schema version 2 without rewriting legacy inventory. DynamoDB adds `META#sub#space` partitions to the existing isolated app table. Spaces are tags, assignments, decks, totals, cards and short-lived locks. No ownership/document TTL is used. Each document stores a version; assignment and tag reference changes commit together. A 45-second owner lease serializes inventory-changing use cases; Lambda's shorter timeout bounds cloud work. Concurrent edits return a retryable conflict rather than silently overwriting data. Tag labels never appear in keys.

Each exact printing/language/finish/condition group has an owned total and location quantities. Classifications consume no copies. Allocations may exceed ownership: `shortfall=max(assigned-owned,0)` and `unassigned=max(owned-assigned,0)`. Lowering a total preserves allocations and creates an inline reminder. Removing or moving assignments, or increasing ownership, recalculates it immediately and on reload. Quantities remain positive bounded integers. A referenced tag cannot be deleted; its label can be renamed and individual assignments removed.

Moxfield snapshots are keyed by provider deck ID. A source lot tracks the highest confirmed contributed quantity for an exact printing/finish within that source, plus its current allocated quantity and section. Moving a card between included sections does not create another copy. An identical snapshot is permanently idempotent; a revised smaller snapshot retains excess copies as loose inventory. New printings/new quantities add only the positive difference. Mainboard/commanders/companions are supported included sections; exclusions are stored explicitly. Source name, canonical URL, folder, retrieval time and recent revision summaries remain available. Each source has a stable deck-location tag whose editable label is independent of later source renames.

Source printings are stored durably before an atomic source manifest commit. Failed metadata writes cannot create ownership. Each manifest is capped at 300 kB and imports at 500 resolved lines, avoiding unbounded transactions. Source contributions aggregate into collection groups using opaque hashed IDs; legacy loose entries are preserved. Unknown source condition uses UNK in this projection without relabeling legacy NM/LP/etc. Manual total changes are stored as a delta, so later newly contributed copies add naturally. Manual location assignments override source allocations and remain intact across source refreshes; provenance still records the original contribution. Source-backed groups do not offer destructive entry removal; source reductions and contextual allocation changes preserve provenance. This is a conservative ownership history, not an automatic mirror that deletes cards when a deck changes.

## Security and deliberate tradeoffs

Source snapshots can retain pending printing-review lines (name, quantity, original set/number/finish and reason). Pending lines do not create owned lots or allocations. Once resolved, the same source ID adds only the previously missing contribution. Canonical name matching includes alternate flavor names, including commander aliases; source labels remain intact.

`transports/response.js` negotiates gzip for JSON responses larger than 1 kB and uses API Gateway's documented base64 binary response envelope. This keeps multi-deck collections below Lambda's response limit without changing the JSON contract or discarding printing metadata. Clients that do not advertise gzip receive plain JSON; very large collections still need future pagination. Domain code does not depend on compression or HTTP. Unit coverage round-trips a large Unicode collection, and LIVE-03 verifies actual gateway compression and decoding.

CloudFront uses an origin access control to a non-public S3 bucket. API Gateway validates Cognito JWTs; only OPTIONS is unauthenticated, for CORS. Self-signup is disabled. The Lambda role accesses only the app's table and log group. The GitHub role trusts only this repository's `main` branch and can deploy only this app's function/site and invalidate its distribution. No long-lived AWS keys are stored in GitHub.

Tokens live in session storage, not URLs or committed configuration. This avoids persistent cross-session login but still requires preventing XSS; view interpolation is escaped and a restrictive CSP disallows arbitrary scripts and framing. Recognition model/worker/WASM are same-origin assets. With backendRecognition:true, bounded card crops go to the isolated recognition Lambda as transient request memory; the scanner discloses this processing and provides source access. With the cloud flag off, recognition uses browser ONNX only. Canonical printing lookups still use the existing catalog backend and Scryfall. Collection and images remain private/public respectively according to their source, rather than pretending public card art is private data.

The UI is a small vanilla DOM app. Screen state is owned by its controllers; it is not a full component framework. Batch orchestration is the largest controller and the first candidate for further splitting as workflows grow. No dependency injection framework or generic repository hierarchy is needed for these two adapters. Local SQLite and cloud DynamoDB are intentionally separate stores, with no automatic migration/sync. E2E coverage must continue to exercise both because their expression/transaction behavior differs.

## Continuous scanner

`public/scanner.js` composes the continuous capture queue and lifecycle. `scan-view.js` renders its shell; `scan-wheel.js` owns FIFO list selection and selected-only controls; `scan-audio.js` owns distinct success/error cues, one-note activation/test sound, mute and persistent AudioContext state reporting. Interrupted/suspended/unavailable states remain visible independently of capture status. Skipped cues expire, so resuming never plays an old success. Native overflow scrolling supplies touch inertia and CSS scroll snap. The current FIFO end uses bottom alignment with no trailing padding. Entering history browsing adds center padding; older selections center with newer entries below. Programmatic selection is immediate so padding changes cannot interrupt an animation and select a neighbor; scroll-end settlement repairs host-specific snap offsets. Keyboard arrows/Home/End and listbox semantics supplement touch. The portrait layout reserves 75% of dynamic viewport height for the camera and 25% for the wheel/footer; short landscape screens reserve a usable 155px panel.

`scan-transition.js` is a pure visual state machine. It compares small frame signatures while recognition is busy, compensates for uniform brightness shifts, requires sustained departure from the last attempted frame, then a stable detailed image before rearming. Recognized names never latch or rearm capture. This permits identical artwork after an observable departure and avoids stationary-frame repeats, but cannot prove physical identity. `camera.js` maps the visible guide into the covered video image so recognition receives the displayed region.

`recognition-candidates.js` resolves model candidate IDs through canonical printing lookups. No model can select an automatic printing. All possible candidates require explicit choice; failed/no-candidate attempts show retry status without entering the wheel, copy count or final form. Finish, condition and ownership require final confirmation. The queue holds at most three waiting images; overflow gives one error cue and drops that attempted frame. Capture IDs remain distinct even for identical names.

`hybrid-recognition.js` starts local preparation at Scan entry and starts one delayed Lambda preparation if local models are not ready after 750 ms. Ready local models take preference; cloud serves during download. A stalled readiness wait ends after 12 seconds per attempted card while preparation may continue. Execution failure can try the other ready/available port once; unknown results are never escalated into confirmation. Stop/dispose cancels pending work. `visual-assets.js` verifies SHA-256 for downloaded and cached assets using content keys independent of release paths; `visual-worker.js` uses CPU WASM and the complete frozen reference index. Cache eviction or unsupported persistence causes a download, not a false cached-ready claim.


Back/Escape opens final batch review and immediately stops tracks, clears the video, invalidates asynchronous work, terminates the recognition worker and closes audio. Background/pagehide stops the same resources; resuming requires a tap. Late camera permissions or model/catalog results cannot repopulate a closed session. Cues fire once per attempted card after resolution, and a muted or unavailable audio context leaves visible status intact. Browser activation is required: see [Chrome audio policy](https://developer.chrome.com/blog/web-audio-autoplay) and [W3C scroll snapping](https://www.w3.org/TR/css-scroll-snap-1/).

## Persistent URL import staging

`adapters/moxfield.js` implements the plain-object `fetchDeck(url)` provider port; `domain/import-draft.js` normalizes public URLs, printing identity and reviewed rows. `application/import-drafts.js` owns fetch/save/Add/Clear, composed with catalog, repository, document store and tagged collection in both roots. `public/import-page.js` handles I/O and dialogs; `import-page-view.js` is escaped rendering. The provider can be replaced without changing ownership logic.

`GET/PATCH /api/import-draft` and POST `/api/import-draft/{fetch,add,clear}` derive owner exclusively from the existing verified JWT transport. One owner-scoped `import-drafts/active` document stores a pending draft or an empty tombstone. Its monotonic revision prevents stale Clear/refetch ABA races. Draft UUID and version are required for writes. Fetch never replaces an existing pending draft; a failed fetch or save leaves it intact. Durable canonical card metadata is separate from ownership and survives the shared cache expiry.

The reserved system tag `system:import-pending` has stable UUID `ae07f79b-38cc-44a2-8fc9-56588cf003ab`, immutable family/key and editable-user-tag-independent identity. It lives in draft lifecycle metadata, never the user registry. Generic tag creation, rename, deletion and assignments reject system status. Collection, totals, normal tags, scanner-owned context and source views read owned projections only; no client-side hiding is relied upon.

Add prepares the existing source import under the owner inventory lock and commits source lots, tag reference changes, permanent `import-receipts/<draft UUID>` and draft removal together in one conditional transaction. A concurrent Clear or edit invalidates the transaction, with no partial ownership. Receipts have no expiry, and permanent source identities prevent later repeated-source imports adding duplicates. Clear writes only the active-slot tombstone. A batch allows 150 lines and 30 distinct user tags, within document/transaction bounds.

Each edited row retains its original fetched line. Source review records retain the whole original snapshot and reviewed count; source display distinguishes these totals. Reviewed lot locations/classifications are defaults. Existing manual allocations remain authoritative, with defaults from newly added sources included until the next manual assignment captures their source IDs. Removed source allocations retain contributed copies as loose inventory. Labels never select structural state.

Moxfield requests use a fixed API host, strict public HTTPS deck URLs, no redirects/cookies/credentials, an honest application User-Agent, a ten-second timeout and a two-megabyte response bound. Denial/private/unavailable/throttled results are explicit errors. The adapter's provisional schema is covered by fixtures, not claimed as a successful live provider contract. Scryfall resolves up to 75 canonical IDs per collection request using the existing shared 600 ms limiter, 24-hour cache and 429 cooldown. Large ingestion still uses bulk data.

## English identity discovery and multilingual names

`shared-search` is a single search region above both the collection and all-card views. It always uses multilingual catalog suggestions and identity resolution; collection filtering is limited to tag/set/finish/color/sort controls. Switching views retains the entered text. `search-ownership.js` aggregates the already verified account's owned projection once per collection state change into Oracle-ID and legacy printing-ID maps. Autocomplete reads these maps without extra inventory calls and updates badges in place so a refresh cannot replace an option under a finger. Ownership never enters the public name-response cache. Saved/loading/failure states remain explicit, quantity mutations invalidate the displayed freshness, account changes clear the projection, and closing suggestions removes their private badge text from the DOM. Pending drafts are not input to this projection.

Autocomplete mouse interaction prevents pointer focus loss and selects on click. Touch interaction does not cancel pointerdown: WebKit can suppress the compatibility click after a canceled touch pointerdown. A stationary single-finger touchend commits selection directly and cancels only that tap's compatibility click. Movement, list scrolling, multiple fingers and touchcancel invalidate the tap; keyboard blur during a pending tap cannot erase its item. Outside pointer input and keyboard dismissal close the list. Selected-card resolution displays an inline opening status and retry control, with the existing generation guard still preventing late navigation.

Autocomplete selection resolves the selected Oracle identity and invokes the same `createCardDetail` path as a grid click; the search generation/abort guard prevents late results opening a card after input or screen changes. Catalog detail immediately shows the reviewed printing and independently refreshes the owned projection. `card-ownership-view.js` matches actual owned rows by Oracle identity (or exact printing ID for legacy metadata), retaining separate printing/language/finish/condition rows. Each row links to the existing assignment editor with its stable inventory ID. Loading/failure never asserts that the card is unowned, and late ownership replies cannot overwrite a closed/replaced detail. No identity-level tags or implicit inventory writes are introduced.

`domain/card-names.js` builds a compact Oracle-ID index from all paper printings with an English representative. Canonical and printed names, including card-face names, become language-labeled aliases. Names use NFKD accent removal, Unicode lowercase, punctuation/whitespace normalization and German sharp-s folding. Exact names rank first (canonical whole-name matches before face aliases), then full prefix, token prefix, substring; if no lexical results exist, a bounded one-edit/transposition fallback applies. Shorter completions break ties before English name and Oracle ID. Alias explanation is decided after ranking: any normalized lexical match against the English canonical name or English face aliases suppresses translated subtext. A foreign-only match retains its language-labeled alias; English aliases need no extra subtitle. This does not change order, rank, completion length or identity selection. Ambiguous normalized aliases retain all matching identities. A token-prefix map reduces autocomplete candidates; substring/fuzzy fallback preserves full catalog coverage. `domain/compact-names.js` implements the same ranking over flat numeric term pairs, shared strings and card records. The binary envelope contains validated lengths, UTF-8 metadata and little-endian numeric terms; gzip bytes are SHA-256 addressed. The browser builds normalization and token postings inside its worker, without constructing an object for every alias; the server snapshot carries those structures precomputed at build time. Token matching avoids per-query token-array allocations.

`adapters/name-index.js` loads a checksum-verified server seed with precomputed normalized names and token postings packaged with Lambda, then checks the public CloudFront manifest in the background. Without a usable seed, the first load shares its download promise. With last-good data, weekly refresh never blocks the requesting search. Failed refresh retains the old snapshot, retries after five minutes and marks stale; no verified data yields a retryable 503. Source age above fifteen days also marks stale. Local mode reads build/catalog. Legacy server JSON snapshots remain readable for compatibility.

`public/name-worker-runtime.js` owns public fetch/decompression/checksum/schema validation, compact search and the weekly-on-use refresh state. `catalog-storage.js` stores one transactionally replaced record (compressed bytes, manifest, last successful check) in keeper-public-catalog-v1 IndexedDB. Reload verifies saved bytes before use; it need not wait for a remote manifest. An updated index is fully prepared before swapping, then persisted; denied/evicted storage allows in-memory search. Old data stays available through download/validation failures. Browser metrics distinguish decode, index construction, refresh, restore, worker search and final dropdown render; events contain durations and public versions, not queries, sessions or ownership.

`public/name-client.js` sends query IDs to a dedicated bundled module worker and receives at most eight public suggestions. The UI thread never receives the full index. Abort/timeout/generation checks reject obsolete replies; worker failure or incomplete coverage uses the existing server endpoint. The complete catalog is downloaded as one object because the measured prototype fits the current transfer budget; no language or prefix shards truncate substring/fuzzy/ambiguous results. Ready local search uses zero debounce, server fallback retains 180 ms. Result cache keys include the worker version.

`application/discovery.js` exposes `suggest` and `discover` through separate `/api/suggest` and `/api/discover` GET routes. Suggestions contain at most 8 names; normal search resolves 24 representative printing IDs, verifies English/paper/Oracle agreement and returns one English card per identity in relevance order. Bounded process caches (100 entries/24h) share in-flight resolution; Scryfall’s existing persistent 24h cache and distributed 600 ms limiter remain authoritative for actual card calls, with429 cooldown. Advanced queries use `unique:cards` and `lang:en`. `/api/search` remains the multilingual exact-printing API for imports, scanner and the new detail picker.

`public/suggestion-view.js` renders escaped suggestion markup with the ownership icon inline beside the name. Current owned/unowned states use checkmark/empty-circle icons; unknown/loading/saved states use distinct question/ellipsis/clock icons with descriptive accessible labels and titles, never quantities or a fresh owned checkmark for stale data. Recent query hints stay separate and recent cards omit historical aliases. Ownership updates change the existing icon in place to preserve pending touch targets. `public/autocomplete.js` controls an accessible combobox/listbox:zero local/180 ms fallback debounce,50-entry/five-minute memory cache, arrow/Enter/Escape/Tab/pointer behavior, IME composition, abort and generation checks. Ordinary prefixes need two characters; CJK input can use one. Only the worker receives the complete public name index. `public/printing-picker.js` allows explicit English/Spanish/all-language exact-printing search constrained to the selected Oracle ID. Detail rules use canonical English `oracle_text`, including faces, even when the chosen physical printing is Spanish. These public query caches are independent of the private IndexedDB inventory snapshots.

`application/discovery.js` accepts an optional selected printing ID with the Oracle ID; both must be valid UUIDs, then actual catalog data must match that printing/Oracle and be English paper. This path skips names.get() and never derives ownership. Legacy Oracle-only and advanced queries remain compatible. `detail-cache.js` holds at most 100 public English cards for 24 hours in page memory, seeds from fetched result pages and never renews TTL on a cache hit. Closing/reopening or signing in to another account does not reuse any private ownership state.

Catalog resolution first asks the printing-cache port for fresh individual IDs, then fetches only missing printings through the existing limiter. Dynamo uses bounded groups of eight GetItem reads under existing IAM (BatchGetItem is not currently authorized); SQLite uses its existing fetched_at column. A printing's search freshness remains 24 hours, independently of Dynamo's existing 30-day retention. The limiter/429 cooldown and explicit ownership mutations are unchanged. Structured server metrics report cache hits/misses and provider/index phases, without user IDs or query text. An index-first stall must not be labeled entirely Lambda init time.

## Dedicated card pages

`card-route.js` serializes exact printing/Oracle references and validates copied or restored links before network access. Optional `entry` identifies an inventory row within the authenticated account; it never selects an owner. The public `/api/card` read supports verified exact paper printings in any language without loading the name index. Ordinary `/api/discover` results and selected autocomplete printings remain English. Provider identity, paper eligibility and digital exclusions are checked; canonical rules text stays English.

`card-page.js` owns one selected page generation and request cancellation. It renders the known name, focused heading, Back and a loading status synchronously, then resolves details using existing printing/Oracle lookup and bounded detail cache. It never fills `cards` or switches to catalog mode. Known grid/Home card data renders immediately. Ownership and image readiness are separate; ownership must refresh from the verified account before showing editable owned printings. Late resolutions, errors and mutation callbacks cannot reopen or navigate away from a newer selection. Sign-out clears the page and private in-memory state.

`card-navigation.js` keeps up to 20 originating view snapshots in memory, including query results, filters, pagination, scroll and focus. Browser history contains only opaque snapshot keys and card references, never inventory rows, quantities, tags or credentials. Back restores the prior view; a copied link without an app-created predecessor returns to Home. Reloading a card refetches/verifies details; reloading an owned entry resolves it only after collection initialization. A missing owned entry stays unavailable rather than becoming Add. Reload does not persist the in-memory prior result list. Back temporarily disables input until history restoration, preventing an early edit from being overwritten. Tag navigation and other view transitions close auxiliary editors.

The main detail is an accessible section inside main, not a dialog. `card-detail.js` keeps existing explicit Add/save/remove semantics, exact printing review, provenance, soft allocation reminders and per-printing tag actions. Printing and tag editors remain auxiliary dialogs; printing choice replaces the current card route while retaining its originating Back destination. Tag saves refresh the current detail context. Form callbacks retain their own elements and only navigate after success when that form is still connected.

`keeper-card-metric` events separate selection-to-page-visible, details-visible (known card/browser cache/network), image-ready and ownership-ready phases. They contain durations/source classifications, not session tokens or inventory. Page-visible records the synchronous DOM transition, not a physical display-paint guarantee. First browser detail resolution can still wait on authentication/network/server cache/provider latency; those delays no longer block the page transition.

## Server recognition (UC-36)

The swappable recognition service lives in recognition/. Its independent visual and text adapters expose a common confirmed/possible/unknown contract with model/catalog/calibration versions and timing evidence. See recognition/README.md for AGPL notices, corresponding source assembly, frozen artifact installation and the administrator review packet. Backend activation uses backendRecognition:true in public configuration only after the isolated service and source-download route pass deployed checks. The isolated resources have administrator approval; application activation still requires actual cloud checks. No model picker is exposed.

The scanner keeps the same visual departure/stability gate, bounded queue, optional candidate review and explicit ownership confirmation. Backend composition cannot automatically confirm printings. It resolves candidate IDs through the existing canonical catalog before offering a choice. Images are transient request memory; there is no image storage or recognition result cache. The UI explains server processing before camera activation and offers an authenticated no-charge Recognition source (AGPL-3.0) download. Stop, Back, sign-out, background and request timeout abort the upload; session guards also discard late results.
