# Product requirements

This document records owner intent, including queued work. It is not proof of production behavior. Latest owner corrections override earlier decisions. Update it for every feature request or correction; connect implemented requirements to use cases, tests and release evidence.

## Status and traceability

Use **queued**, **in progress**, **locally verified**, or **production verified**. Production verification requires an identified release and relevant live evidence. The entries below capture the active interaction revision and known backlog on September 9, 2026. This PR is in progress; the active requirements below are not yet production verified.

## Active card interaction revision — in progress

| ID         | Requirement and acceptance criteria                                                                                                                                                                                                                                                                                                    |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CARD-01    | All card grids show card images without metadata underneath; use narrower gaps. Preserve accessible names.                                                                                                                                                                                                                             |
| CARD-02    | Pointer movement continuously tilts the card toward the pointer. Hover immediately reveals collection-specific information; after **300 ms**, lift to 200% of the rendered tile size. Leaving before the delay cancels the lift. Tilt remains active on the enlarged card.                                                             |
| CARD-03    | Click/tap enlarges the card **in place over the visible page**, preserving its source slot, filters and scroll. Target 300% of the rendered tile size, capped initially to show the complete card with usable outside-dismissal margins. Shift minimally for viewport edges; never unconditionally center on the screen.               |
| CARD-04    | Information stays near the card's left edge and actions near its right edge. Smaller screens allow progressively more overlap while keeping the card's center and dismissal margins usable. No detached screen-edge controls or encompassing control panel.                                                                            |
| CARD-05    | Do not repeat printed card name, rules, type, set or collector number in hover/zoom overlays. Show collection-specific information and actions. Tags display plain names without decorative squares or quantity suffixes. Preserve underlying ownership and location quantity semantics.                                               |
| CARD-06    | Controls use restrained translucent glass surfaces, illuminated edges, subtle action-specific tints and interaction-responsive light/depth. Dark shadow blobs, opaque rings and generic large button panels do not satisfy the visual requirement. Load licensed fonts deliberately; verify actual font loading and readable fallback. |
| CARD-07    | Zoom uses smooth overshoot-and-settle spring motion. Keep a single solid lifted card rather than overlapping translucent copies. Avoid layout jumps, pointer stutter, text selection and native image dragging during active drag. Restore normal selection afterward.                                                                 |
| CARD-08    | Wheel/pinch adjusts zoom; deliberate enlargement permits bounded panning. Outside click/tap closes and consumes the gesture without activating underlying content. Reset restores the comfortable initial view; preserve keyboard dismissal and reduced-motion behavior.                                                               |
| DRAG-01    | Dragging a card directly reveals a radial action wheel around the selected card. No three-dot/dropdown trigger. Use true sectors, an open center and readable unclipped targets.                                                                                                                                                       |
| DRAG-02    | Recent/relevant tags are easiest to reach; less relevant actions remain available through outer choices or More. Freeze target geometry during a gesture. Maintain continuous outward movement to select an action.                                                                                                                    |
| DRAG-03    | Keep the selected card unmistakable in the wheel center; adapt once for viewport edges. The moving card becomes translucent over targets. Do not obscure labels or substitute a tiny moving thumbnail. Preserve quantity, ownership and tag-ID rules.                                                                                  |
| PERF-01    | Compare actual visual implementations, including the WebGL experiment, using equivalent interactions. Choose by visual result and measured responsiveness, not renderer name. Test dense grids, narrow phones, landscape, wide screens, interruption and failure paths. Do not describe emulation as physical-device verification.     |
| QUALITY-01 | Iterate locally and inspect real screenshots and motion before release. Passing tests alone is insufficient visual acceptance. Integrate and deploy through the normal workflow when the requirements are met; record remaining limitations honestly.                                                                                  |

Superseded: 200 ms hover delay; unconditional 300% opening on phones; viewport-centered click inspector; repeated printed metadata; small moving drag thumbnail; wheel opened through an actions menu.

### Current evidence

CARD-01–08 and DRAG-01–03 are implemented locally in PR #13; final anchoring and hover boundary checks are running. CARD-02 targets 200% subject to a 16px viewport edge fit; CARD-03 targets 300% subject to 24px horizontal/32px vertical safe-area dismissal gutters. CARD-07 covers the zoom spring; flip remains queued as CARD-09.

Traceability: [card use cases](USE-CASES.md), [layout/gesture architecture](ARCHITECTURE.md), [application interaction tests](../tests/ui/card-actions.spec.js), [prototype geometry and timing tests](../tests/prototype/geometry.spec.js), [font/glass/failure checks](../tests/prototype/fit-fonts.spec.js), and [measured dense-grid limits and historical comparisons](../tests/performance/CARD-ACTIONS.md). Actual public-image v18 wide/phone captures were independently reviewed before release. PERF-01 records Chromium 16.7–16.8ms frame p95 and WebKit drag 30ms p95 on this host; physical hardware is unverified. QUALITY-01 remains in progress until exact-source publication, deployment and relevant live checks complete.

## Frontend deployment workflow — in progress

- **DEPLOY-01:** Provide a frontend-only path through the existing main deployment workflow for eligible UI changes. Publish versioned frontend assets without rebuilding or updating unchanged application/recognition backends or model assets.
- **DEPLOY-02:** Determine eligibility from the change set and explicit compatibility rules; backend, API-contract, recognition or infrastructure changes require the full path. Unknown changes must not silently take the fast path.
- **DEPLOY-03:** Keep frontend and backend release identities independently accurate, retain atomic HTML publication and rollback/version ordering, and preserve the complete corresponding source offer for the deployed combination.
- **DEPLOY-04:** Run meaningful frontend/browser/build checks and live compatibility smoke checks using separate test profiles. Measure total deployment time against the full workflow. Reuse verified immutable artifacts; do not weaken integrity checks, permissions or owner-data protection to gain speed.

Initial implementation is isolated in `codex/frontend-only-deploy`. The release classifier has explicit presentation inputs and a full-release fallback for missing metadata or unknown changes; pipeline reuse, source composition and production verification are not implemented yet. [Use cases](USE-CASES.md) and [classifier tests](../tests/release-plan.test.js) record coverage.
