# Product requirements

This is the authoritative requirement ledger. Stable IDs are never reused. Status distinguishes owner intent, local implementation, merged code, and production evidence. Detailed behavior lives in [SPEC.md](SPEC.md), architecture decisions in [ARCHITECTURE.md](ARCHITECTURE.md), observable journeys in [USE-CASES.md](USE-CASES.md), and release evidence under `tests/performance/`.

## Status vocabulary

- **Production verified:** exact deployed revision and relevant live evidence exist.
- **Delivered:** merged or released evidence exists, with any remaining evidence gap stated.
- **Locally verified:** implementation and local checks exist; merge/deployment is not claimed.
- **Accepted / queued:** owner intent is saved; implementation is not claimed.
- **Superseded:** replaced by a later stable requirement; retained for history, not requeued.
