# Product requirements

This is the authoritative requirement ledger. Stable IDs are never reused. Status distinguishes owner intent, local implementation, merged code, and production evidence. Detailed behavior lives in [SPEC.md](SPEC.md), architecture decisions in [ARCHITECTURE.md](ARCHITECTURE.md), observable journeys in [USE-CASES.md](USE-CASES.md), and release evidence under `tests/performance/`.

## Status vocabulary

- **Production verified:** exact deployed revision and relevant live evidence exist.
- **Delivered:** merged or released evidence exists, with any remaining evidence gap stated.
- **Locally verified:** implementation and local checks exist; merge/deployment is not claimed.
- **Accepted / queued:** owner intent is saved; implementation is not claimed.
- **Superseded:** replaced by a later stable requirement; retained for history, not requeued.

### B-04 runtime availability

**Locally verified:** Keeper owns the Python 3.12 prerequisite of its declared `prepare:validation` command. Readiness requires either an installed Python 3.12 discoverable in the launch environment or a documented, reproducible Keeper bootstrap for that runtime. Nexus executes the declared commands; it is not responsible for installing this project runtime. Verification is limited to the current Windows host; an unconfigured host must still install the documented prerequisite.

Acceptance: from a fresh clone, `npm ci`, `npm run prepare:validation`, and `npm run validate` pass unattended in the documented launch environment. Preparation must resolve Python 3.12 before installing visual dependencies, preparing recognition assets, building the name index, and installing Chromium. A missing or incompatible runtime must produce an actionable error.

The earlier clean-clone timings remain valid for their prepared environment. They did not establish readiness in the current launch environment, where `selectPython312()` reported that Python 3.12 was unavailable. The selected smallest supported resolution is the official Python Software Foundation `Python.Python.3.12` WinGet package installed per-user. Keeper selects `py -3.12`, leaves the existing Python 3.14 default unchanged, preserves `KEEPER_PYTHON`, and performs no Nexus or shared configuration change. Successful application deployment alone did not close this setup gap; the fresh-clone setup and validation below do.

Direct verification on September 20, 2026 at 19:20 UTC used a fresh remote clone of `b72e1ad1692daa1166f2ca78df774a12b36bf165` and the inherited host environment, with no `KEEPER_PYTHON` override. `npm ci` passed in 2.86 seconds. `npm run prepare:validation` exited 1 after 0.35 seconds: `Python 3.12 was not found. Put it on PATH or set KEEPER_PYTHON to its executable.` Validation was not run after failed setup. The unattended-setup acceptance check therefore failed on this host; no Nexus run, runtime installation, or host configuration change was performed.

On September 20, 2026, the current Windows host installed Python 3.12.10 per-user through the hash-verified WinGet package published by the Python Software Foundation. `py -3.12 --version` then reported `Python 3.12.10`, while both `py --version` and `python --version` remained `Python 3.14.3`. The repository documents that supported prerequisite and its non-interactive command; the existing selector and corresponding-source guard remain unchanged.

Unattended verification then used a fresh remote clone of unchanged `main` commit `b72e1ad1692daa1166f2ca78df774a12b36bf165` in the normal inherited environment with `KEEPER_PYTHON` absent. `npm ci` passed in 2.92 seconds, first-workspace `npm run prepare:validation` passed in 46.06 seconds, and `npm run validate` passed in 77.27 seconds with 151 Node tests, 27 Python tests, the build, and 150 Chromium browser tests. The workspace began without ignored/generated repository inputs, while npm, pip, browser, model, and network caches outside the clone were warm; these are not cold-network timings or production-delivery evidence. The existing selector and recognition corresponding-source guard remained unchanged.
