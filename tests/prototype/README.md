# Local card motion prototype

This development harness compares the shared application interactions with public sample data. It has no deployment or account access. The application uses the SVG glass renderer; the real WebGL lighting variant is retained here for repeatable comparison.

Run `node tests/prototype/serve.mjs` from the repository root and open http://127.0.0.1:3120/. The server listens only on loopback. It serves the actual shared card renderers, gesture controller, inspector and styles with a restrictive content security policy. It has no account or API routes. Sample quantity edits stay in memory; other actions display their selected label. Reload resets the sample state.

The public sample is White Sun's Twilight, ONE #377, English. Its normal and large images are full-card Scryfall variants. Deck, owned collection, Catalogue and Home surfaces use the application's renderers. The 1,000-card setting repeats this printing: it exercises DOM density but does not simulate 1,000 independent image decodes.

Hover aims for twice the source tile with 16px viewport margins. Inspection opens at up to three times the source, reduced as needed to show the full card with 24px horizontal/32px vertical dismissal gutters plus safe areas. Percentage is truthful; its Reset button restores the opening fit. Independent glass controls stay on the right and collection information on the left. Printed metadata is not duplicated. The centered wheel pickup is opaque while the source is hidden; it shrinks only enough to keep labels clear. The moving ghost retains source size and grab offset. Reduced motion removes reveal animation. A failed or late high-resolution decode cannot replace an unrelated image.

Run `npx playwright test -c tests/prototype/playwright.config.mjs` for Chromium and WebKit checks of all four surfaces at 1280×800, 390×844, 320×568 and 844×390, fitted geometry and outside dismissal under CSP, overlay bounds, image upgrade failure/departure, interrupted reveal, Back and 1,000-card density. These checks use deterministic SVG image fixtures. `tests/ui/card-actions.spec.js` additionally verifies the actual application quantity failure/retry/persistence, account isolation, outside dismissal, reduced motion, controlled pinch/pan, touch-scroll cancellation and frozen drag targets.

The September 9 review clips use actual Chromium video capture and the public card image, encoded as H.264/yuv420p MP4 with faststart. They show hover into the inspector, a 390×844 touch-emulated inspector with pinch/pan, and the drag wheel. They are browser recordings, not interpolated animation or physical-phone verification. Local media paths alone do not establish phone playback or delivery. No production writes, credentials, owner inventory or recognition changes are involved.

Select **SVG glass** or **WebGL lighting**, or open `/?renderer=webgl`. WebGL uses a real vertex/fragment program, convex surface normals, pointer-following lighting and glow, one reusable context and no idle render loop. It composites transparently over the page; it does not refract the underlying DOM. HTML labels and polar hit sectors are shared. Unsupported contexts and context loss preserve SVG actions. `webgl.spec.js` tests actual contexts and both fallbacks in Chromium and WebKit.

Run `node tests/prototype/capture.mjs hover <output-directory>` with `FFMPEG_PATH` pointing to an installed ffmpeg executable. Other modes are `phone`, `drag`, `drag-phone`, `drag-small`, `drag-tablet`, `drag-landscape`, `drag-webgl` and `drag-phone-webgl`. Capture uses real CDP screencast JPEGs and their timestamps, then encodes variable-frame-rate H.264/yuv420p MP4 with faststart. JSON evidence includes input scene, dimensions, capture timestamps and bounded motion samples. No frames are interpolated. Native emulated touch dispatch can deliver fewer changed frames than the display animation; do not call every clip 60 fps.

The September 9 comparison ran through Chromium's ANGLE SwiftShader software backend. Desktop changed-frame interval p95 was approximately 18 ms for SVG versus 34 ms for WebGL; median intervals were approximately 17 ms for both. WebGL initialization took about 4–5 ms and CPU command submission was usually under 0.1 ms, but GPU completion timers were unavailable. These are single-host observations, not physical GPU or phone measurements. The additional lighting was subtle and did not justify its observed frame cost; SVG is the production choice. Soft text backing, clear pickup identity, bounded source-relative zoom and continuous motion provided the more useful visual improvements.

The subsequent fit/font review supersedes the earlier exact-scale design and renderer acceptance described above. Add `animation-module` as the fourth capture argument for the public KLD #194 example. Inspector modes `phone-small` and `phone-landscape` record full-card opening and a native emulated outside dismissal. `fit-fonts.spec.js` verifies loaded/failed/delayed self-hosted fonts, actual Chromium display face, unchanged active wheel labels and safe-area/browser-chrome simulations. These are browser checks, not physical-device evidence. Current comparative WebGL shading is flatter and more transparent; it remains local and must be judged against matching SVG captures, not selected by name.
